# 竞技场深度统一设计（训练场 × 决斗场 合并）

> 状态：设计稿 **v2（2026-09-10 已确认）** · 分三期实施，每期结束管理员 iPad 实测后再进下一期
> 范围：把「单人训练 5 题型」与「真人 PK」合并为同一个竞技系统，
> 共用回合模型、结算、战绩、段位、排行榜，而不是只做一个壳。

---

## 1. 目标

1. 学生只有一个入口心智：「做题对战」= 同一件事，可选对手（自己 / 真人）。
2. 经济规则一套：入场费 → 作答 → 结算（加分/扣分）全部服务端记账，消除本地 localstorage 战绩。
3. 战绩统一：单人练习的正确率/连对/今日题量 与 决斗胜负 合并成一套"熟练度 + 段位 + 今日进度"。
4. 老师可见：练习行为可统计（目前单人训练完全在前端本地，后台看不到学生练没练）。

---

## 2. 核心抽象：一"局"（Session）

所有玩法收敛成同一个模型：

```
一局 Session = 模式(Mode) × 对手(Opponent) × 赌注(Stake)
```

| 维度 | 取值 | 说明 |
|------|------|------|
| 题型 Mode | s2m 据句选义 / m2s 据义选句 / cloze 挖空默写 / judge 义项速判 / couplet 名句接龙 / duel 抢答四选一(现决斗题型) | 训练 5 种照搬 + 决斗题型并进来 |
| 对手 Opponent | none（单人）/ human（真人匹配）/ bot（陪练机器人，**暂不做**） | human 需匹配；none 随时可开 |
| 题量/时限 | 默认 10 题；对局每题 20s（沿用决斗节奏），单人可自选 5/10/15 | |
| 赌注 Stake | 单人：6 入场，答对 +1/题（封顶 = 题量）；真人：50 入场，胜 +100 / 平退费 / 负不退 | **金额维持现状**（见 5.2） |

结论：决斗场 = 对手维度切到 human 的一局；训练场 = opponent=none 的一局。
现有 `/battle` 的全部子流程（匹配幕/竞技幕/结算幕/段位徽章）保留复用，只是从"独立入口"变成"一种模式"。

## 3. 后端设计

### 3.1 数据表（新增，不动 battles/coins_ledger 旧表）

```
arena_sessions  (一局的档案，单人局也从这里走，解决"训练看不见"问题)
  id, user_id, opponent_type(none|human), mode, deck_id,
  total_questions, correct_count, wrong_count, score, duration_s,
  entry_fee, reward, status(open|done|abandoned), result_key(win|lose|draw|finish),
  battle_id NULL(单人) / battles.id(真人局引用), created_at

arena_ranks    (段位/熟练度；段位只看真人胜场，见 5.4)
  user_id, rank_key, total_sessions, total_score, streak_best ...
```

说明：
- 真人局继续写 `battles` 表（现网结算/强制机制不动），结算时**顺带写一条 arena_sessions**，战绩查询统一走 arena_sessions。
- 单人局由服务端开/结：`POST /api/arena/start`（扣 6、出题）→ `POST /api/arena/answer`（逐题判分、落正确数）→ `POST /api/arena/finish`（本地把 10 题答完后统一结算 + 奖励）。
- **出题下沉到服务端**（深度服务端化，见 5.1）：复用 battles.ts 的 buildQuestions 思路 + TrainingPageV2 的题型逻辑（cloze 挖空/judge/couplet 需要把 makeCloze/splitVerse 逻辑搬到 server）。此后单人训练的干扰项池、出题都与决斗同源，前后端不再各写一份。

### 3.2 API（新路由 /api/arena/*）

```
GET  /api/arena/home          → 余额、今日单人题量/正确率、决斗战绩、段位、排行榜摘要
POST /api/arena/start         → {mode, opponent:'none'|'human'} 校验铜板→扣费→出题(存服务端)
POST /api/arena/answer        → {sessionId, index, choice|text} 判分，返回对错/正确答案
POST /api/arena/finish        → 结算（写 arena_sessions + coins 流水）
POST /api/arena/abandon       → 单人中途退出：已答对 ≥1 题按比例退/发奖，杜绝"白扣 6"
GET  /api/arena/leaderboard   → 今日榜/总榜（单人正确题 + 决斗胜场折算的"竞技分"）
POST /api/arena/human-match   → 现 /api/battles/match 的别名，进入真人局（保留 cancel + 60s 清扫）
```

### 3.3 经济结算规则（服务端权威，全走 coins_ledger 流水）

| 场景 | 扣/得 | source |
|------|------|--------|
| 单人开一局 | -6 | arena_entry (含 mode) |
| 单人答对 | +1/题 | arena_correct |
| 单人中途放弃 | 已答对的部分照发，未答部分不退（= 白练的收场不亏也不赚）| arena_abandon_refund 兜底 |
| 真人局 | 沿用现 battles 规则 | battle_entry / battle_refund / battle_win（不动）|

> 单人奖励上限封顶题量，防刷：目前训练 report 允许 0-20，但轮内最多 10 题正确；
> 统一后由服务端按实际 correct_count 入账，天然封顶，上报造假通道关闭。

## 4. 前端设计

### 4.1 导航（P1 落地）
底部导航合并为 **5 项**：首页 / 学习 / **竞技场** / 一起背 / 商城
（训练场 + 决斗场 两个入口合并为「竞技场」；原第 6 位不再保留，图标做大、iPad 触屏友好）。

### 4.2 页面结构（/arena 新路由，P1 先搭壳，P2/P3 填充深度）
```
竞技场首页 (ArenaHub)
├─ 顶栏：余额 + 今日进度(题数/正确率) + 段位徽章 + 排行榜入口
├─ 大卡①「单人练习」：5 个题型胶囊(每个显示可练题数) + 选卡组 → 开始（扣 6）
├─ 大卡②「真人 PK」：段位/赛季战绩/规则 → 匹配对战（扣 50，流程=现 BattlePage）
└─ 底部：战绩页（单人记录 + 决斗记录并列表格，日期/模式/结果/得分）
```
- 模式选择（单人）= 现 TrainingPage 的模式选择页改版，保留 5 题型视觉。
- 对局页：单人局 = 现 TrainingPage 的作答器（视觉不动）；真人局 = 现 BattleArena。
- 结算页：统一一套 —— 答对 X/10 · 得分 · 铜板 ± · 再练一局 / 匹配对战 / 回首页。

老路由：/training 与 /battle 302 → /arena（旧书签不丢）。

### 4.3 交互原则（iPad 触屏）
- 单人中途退出加「放弃本局」按钮 + 弹窗确认（写明"已答对的会照发铜板"），杜绝再次出现"扣了钱没说法"。
- 匹配取消按钮沿用本次修复的退款逻辑（见 6.1 已上线）。

## 5. 已确认决策（原开放问题，2026-09-10 管理员拍板）

| # | 问题 | 决策 |
|---|------|------|
| 5.1 | 单人训练要不要服务端化？ | **A 深度服务端化**：出题/判分全走服务端，后台可见每题细节；cloze/couplet 逻辑移植到 server（P2 主工作量）。 |
| 5.2 | 入场费/奖励是否调整？ | **维持现状**：单人 6 / 真人 50（胜 +100）。真人 50 对班级偏贵但规则不变，后续可单独评估。 |
| 5.3 | 单人训练与每日任务关系？ | **纳入**：把"竞技场练 20 题"加入每日任务体系，完成后可领铜板（P3 接入，依赖 arena_sessions 落库）。 |
| 5.4 | 段位/连胜怎么算？ | **段位只看真人胜场**（沿用现有逻辑）；单人局只累积"今日进度 + 总练习榜"，不参与段位。 |
| 5.5 | bot 陪练（可选） | **暂不做**：防止"匹配 60 秒无人→劝退"的备选方案，留作后续独立评估，不进入本期三期。 |
